# 测试与验证

## 最低要求

- 仅文档调整：检查链接、路径和描述与仓库一致。
- TypeScript 或配置调整：运行 `npx tsc --noEmit`。
- 页面或组件调整：在类型检查外，实际打开页面并完成相关点击流程。
- API 或同步调整：验证成功、未登录、无效输入和重复请求。
- 数据库调整：使用新迁移，检查 RLS 与旧数据兼容性。

## 前端验收原则

前端流程必须通过真实页面操作验证，不使用直接调用后端接口来替代点击、输入、跳转和状态展示。接口测试与页面测试是两类独立验证。

## 记录方式

任务进行中时，把验证项和结果写在对应的 `docs/work/<task>.md`；较复杂功能复制 [`feature-test-template.md`](feature-test-template.md)。任务归档时保留最终结果，删除无价值的调试日志。

## 分层测试

- 逻辑测试：纯业务规则、排期、计数和权限判断。
- API 测试：身份校验、输入校验、重复请求、错误码和数据副作用。
- 浏览器测试：通过真实入口完成点击、输入、跳转、刷新和状态展示。

不能只测试 API 后声称用户流程已经完成；也不使用大量慢速页面测试替代适合逻辑或接口层验证的组合。
